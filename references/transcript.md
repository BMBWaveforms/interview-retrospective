# 从输入到可引用原话

**文本。** 保留原有用字、标点、换行、语气词、重复、自我更正和原有时间。没有时间就引用段号 L001… 并注明“文本未提供时间戳”。只有摘要或回忆时标为“非逐字材料”，只引用确实给出的文字，请用户提供录音／原稿再形成完整逐字复盘。不能把回忆扩写成访谈。

**音视频。** 确认文件可解码、有声音、音轨／语言正确；多段文件确定顺序。优先离线识别。先检查可导入 faster_whisper 的 Python 和已缓存模型；附带脚本直接接受带音轨的视频或音频（需要 ffmpeg，默认首条音轨），仅使用本机模型，拒绝覆盖已有输出：
```
<可导入 faster_whisper 的 python> scripts/transcribe.py <媒体文件> --language zh --output <新的片段.json>
```
语言不明时省略 --language，多语言按原语种保留；有可用 uv 与依赖缓存时也可从 Skill 目录尝试 `uv run --offline --python 3.12 --with faster-whisper python scripts/transcribe.py …`。若视频多音轨，核实目标音轨后用 ffmpeg 选取，记录相对于原媒体的起点。长录音拆片时保存每片起始偏移，重叠处比对同一发言后去重。多份媒体按“文件名 + 文件内时间”定位，不猜中间间隔。

**初稿与AI复核。** 时间使用 [HH:MM:SS.mmm–HH:MM:SS.mmm]。AI负责转写、分角色、时间对齐和语义复核，不把逐段复核工作交给用户。优先使用可听辨音源的能力；若只有离线识别能力，可用不同本地模型交叉转写，检查对话承接、首尾和段间空白，单独核对否定、数字、术语、抢话与角色边界。识别器片段可能跨越两人，不能把片段编号直接当作说话轮次。清楚注明实际方法，不将重复ASR称作“已回听”或“逐字核听认证”。不能可靠确认的词句或身份不补造，不据此扣分；只有缺口确实影响公司、岗位、轮次等关键事实时才集中向用户询问。
- 无法辨认写作 “[听不清 00:02:11–00:02:14]”；多人重叠写 “[重叠发言，无法区分 …]”；文件中断单独标出。保留能确认的前后词，勿依据 JD 猜词。无声音、无可用解码／识别能力时明确缺口，请求原稿或其他录音。
- 不能确认身份时用“说话人 A／B（角色待确认）”，按声线和证据保持编号一致；涉及评分且无法可靠区分身份时，先排除该段；只有排除后仍无法形成有效复盘才询问用户。多位面试官分别编号。能识别的一方先记，不因角色不清编造另一方。原始媒体默认不外传。已有获准访问的妙记可读带时间和说话人的逐字转写；如改用上传转写，先告知服务和上传范围，取得这次对原始媒体的授权。
- 用户已经提供带说话人和时间戳的逐字文本时直接使用，保留标注。不把翻译、摘要、语病修正或产品名猜测混入原话。

**切题。** 每次面试官独立提问编 Q01、Q02…；为上一题索取细节或理由的追问编 Q01.1、Q01.2，标题保留追问原话，各自关联实际答复与来源。一次发言连问数点、用户合并作答时作为一道含子问的问题，不把同一回答重复计分。同一回答分几次发言则分开保留，中间面试官插话保留在本地完整转写。候选人反问、寒暄和结束语同样保留在本地，只有面试官实际考察的问题才评分。没有用户发言时，题下注明“未作答”“被打断”或“资料缺失”的证据；原话代码块留空，不往空块里塞一段假回答。本地完整转写按原顺序包括全部发言及缺失标记。交付前逐条比对题目、回答与本地转写的原文及定位；归档正文不输出完整转写附录。回答代码块只改变显示自动换行，不为排版插入硬换行或改写原话。
