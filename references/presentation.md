# 正文展示规范（强制）

归档文档用于阅读和备答；溯源校验留在本地。生成、修改及交付回读时均执行以下要求。

## 可见内容

- 禁止正文显示SHA-256等长指纹、token、table_id、record_id、block_id、机器段号、提交结束标识或本地绝对路径。原生块属性和链接目标中必需的ID不属于可见正文；不要把它们另写成文字。
- 来源使用“查看招聘原文”“面试进度表”等链接名，保留真实URL。日期、岗位、轮次和原文件名可见；版本用可读日期说明，不用内部编码。
- 正文结构为：岗位信息与JD → 各轮问答及原视频 → 各轮本轮报告。每轮到报告结束；不输出完整转写附录、评分证据底稿或其后的技术内容。完整转写、计算底稿与来源映射保留在本地。
- 清理已有多轮文档时按每轮边界处理，保留后续轮次。原视频、原话、用户已填写的黄色块不因排版而重建或清空。

## JD

先用两列表格列出公司、岗位、JD读取日期与来源链接。JD正文统一用“类别｜JD原文”两列表格，按岗位职责、任职资格、加分项归组：每个类别只占一行，同类完整内容集中在右侧同一个单元格，保留原文换行。禁止每条要求单独成行、重复填写类别，禁止增设条目/序号列或叠加自动编号。原文自身编号仅出现一次。

保留全部原文、数字、条件及类别内顺序，不用摘要替代。将“任职要求”“核心技能要求”归入任职资格；原有子标题可在同格内保留一次。只展示原JD实际提供的类别，不为凑齐三类臆造加分项，也不擅自拆出含“优先”的句子。仅清除抓取容器引号、导航和广告，不润色JD。类别列约100px，正文列占剩余主要宽度；回读核对每类一行、每条原文恰好一次、没有额外编号列。

## 回答代码块：必须自动换行

所有回答使用选定载体的纯文本代码块，并开启显示自动换行；按 [格式适配](formats.md) 验证实际效果。

**飞书 Docx：** 使用原生PlainText代码块，实际属性必须为 `code.style.wrap=true`。仅添加 `<pre wrap="true">` 或本地CSS不能证明飞书已设置；不通过插入硬换行改变原话来模拟自动换行。

写入后在公司写入锁内运行：

```bash
python3 scripts/wrap_code_blocks.py DOCUMENT_ID
```

可重复使用 `--block-id` 只处理指定代码块，`--inspect` 只读检查。脚本只修改自动换行字段，回读核对全部目标代码块仍保留原文字。跨版本使用前核对本机CLI及官方API。若实际设置失败，明确报告尚未完成，不能宣称已修好。

**本地 HTML：** 使用 `pre { white-space: pre-wrap; overflow-wrap: anywhere; }`。原话含有的换行、空白和字符仍须逐字保留。

## 评分与本轮报告

1. 概览表突出“综合分 /100、有效评分题数、红题数、黄题数”；先看到分数，再看到简短结论。
2. 五维表格展示“维度｜得分 /5｜可视条｜有效题数｜本轮证据”。可视条统一为十格方块，说明每格代表0.5分，仅作近似展示，数值为准。未考察或无法评价显示文字及原因，不画零分条。不能用红黄诊断颜色暗示分数阈值。
3. 优势与短板各用简短行，带本轮题号。红黄建议已在题下完整出现，报告只列关键题号和准备重点，避免再次堆成长段。
4. 优先准备动作每项独立一行，明确先回看哪题、补什么真实材料或判断依据；不代写答案、不编造经历。
5. 评分方法仅简短解释60/40分组、未考察不计零和覆盖范围。完整计算过程与逐题五维理由留在本地。

排版调整必须保持原评分、权重与null口径，不重新解释录用结果。在本次选定格式中回读表格、代码块实际换行、原视频、黄色输入块，以及正文无技术ID和附录；飞书另外核对原生块属性。

## 原生换行接口依据

官方[块的数据结构](https://open.feishu.cn/document/docs/docs/data-structure/block.md)定义 `TextStyle.wrap`；[批量更新块](https://open.feishu.cn/document/server-docs/docs/docs/docx-v1/document-block/batch_update.md)的 `update_text_style` 用 `style: {"wrap": true}`、`fields: [5]` 仅修改换行。当前XML导入指南未提供此设置，须写后单独设置并读取实际属性核验。
