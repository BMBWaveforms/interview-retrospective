# 本次归档设置

每次向使用者确认两项：**格式与排版**（文档平台／文件类型、是否有模板）以及**精确的归档位置**（本地目录、飞书父节点或具体公司文档）。同时收取独立的 JD 入口；不能把 JD 库当归档位置。两项都确认后才创建或写入。如使用者只要求预览，返回草稿。提供模板时保留模板已有结构和内容；如果模板无法表示原视频或可编辑的黄色空块，先说明具体缺口，询问如何适配。不要默默更换格式。

- **飞书 Docx**：使用 feishu.md 的 revision-id、原生代码块、引用块和空段落 callout；用 video.md 插入原文件。指定的是已有文档时，先确认所属公司；如果是知识库父节点，查重后创建或追加。如为用户指定的其他飞书父类型，按 CLI 当前帮助解析位置，不使用不相关的 Wiki 节点。
- **本地 HTML**：在确认的目录按公司建立可携带的文档。视频保留原名，放到按原件 SHA-256 分隔的相邻资源目录，使用相对路径的 video controls 和原件下载入口；复制后校验哈希。逐字回答用 pre/code，诊断用 blockquote。黄色输入区初始值为空，必须实现并测试填写后保存、关页重开和导出恢复。仅 contenteditable 不构成持久保存；可用显式“保存已填写版本”导出完整可携带的编辑稿，保留相对资源路径。交付时说明需要哪一步保存。不要把本机绝对路径写进共享页面。
- **Markdown 或其他格式**：先检查目标编辑器能否持久保存黄色可编辑块、原件视频和所需段落。纯 Markdown 的代码／引用可保留，黄色空块及内嵌播放器依赖宿主。无法同时满足时先说明缺项，让使用者选支持的载体（如飞书、HTML）或明确接受的具体降级方案。不能把外链或截图说成已嵌入原件；对平台无写入能力时交付已确认格式的本地草稿并说明还未归档。
- **幂等与恢复**：复用 feishu.md 的公司业务键、来源哈希、轮次指纹、部分完成核对原则。对本地文件同公司串行写；持锁比较读时和写前文件摘要，临时文件完整写好后同目录原子替换，文件冲突先重新读取。新文件用独占创建，副本或同名多份先消歧；已有内容、用户输入或媒体永不以模板覆盖。素材可先写入来源指纹命名目录再提交文档；中断后校验已有素材、仅补缺失部分。交付前在用户实际格式中回读逐字稿、评分、空块编辑保存及每个视频的定位和字节。
